# 開発手順

Python 3.12とGit、GitHub CLIを使用します。配布用生成ツールはWindows上のRust 1.90.0とMSVCでビルドします。ゲーム原本を必要とする抽出はローカルのみで行い、公開データからの検査・ビルドはゲームを持たない環境でも再現できる構成にします。

## ブランチとIssue

`develop` が開発・既定ブランチ、`main` が公開ブランチです。Issueごとにdevelopから作業ブランチを作り、検証後にdevelopへPRを提出します。PR本文に `Closes #番号` を記載します。既定ブランチの変更にはGitHubのAdministration権限が必要です。

初期コミットとGitの作者設定は変更しません。新規コミット、Issue、PRの説明は日本語にします。

## 公開データの境界

原文、抽出資産、実機ログ、画面写真は `.local/` に保存します。`.local/` と `.tools/` はコミットしません。秘密情報を含むコマンド結果を会話やGitHubへ貼り付けないでください。

公開前検査は次のコマンドで実行します。検出値そのものは表示しません。

```powershell
py -3.12 scripts/check_public.py --staged
py -3.12 scripts/build_runtime.py
py -3.12 -m unittest discover -s tests
```

Gitの除外設定だけで安全性を保証せず、明示的なファイル追加と差分レビューを併用します。リポジトリ公開時には全ブランチ、Issue、PR、Actionsのログと成果物も確認します。

## 公開条件

日本語表示の試作、翻訳・構造検査、導入・削除テスト、ユーザーによる製品版の通しプレイを完了させます。公開候補ZIPとチェックサム、既知の制限を提示し、承認後にdevelopをmainへマージコミットで統合します。リポジトリの公開切替も最終承認後です。
